# Terraform: AWS production environment

This folder provisions everything Ikimina Tracker needs on AWS. Ansible then
configures the VMs (see [../ansible/README.md](../ansible/README.md)), and the
CD pipeline deploys to them. The architecture diagram is in the
[main README](../README.md#2-architecture).

## What gets created

| Resource | Terraform name | Purpose |
|----------|----------------|---------|
| **VPC** `10.20.0.0/16` + internet gateway | `aws_vpc.main`, `aws_internet_gateway.main` | Private network |
| Public subnet `10.20.1.0/24` | `aws_subnet.public` | Bastion host only |
| **Private subnet** `10.20.2.0/24` | `aws_subnet.private` | App VM (no public IP); default route through the bastion (NAT) |
| Database subnets `10.20.3.0/24`, `10.20.4.0/24` | `aws_subnet.database` | Two AZs (RDS requires it); no internet route |
| Route tables | `aws_route_table.public/private/database` | Public → internet gateway, private → bastion NAT, database → local only |
| **Security group** bastion | `aws_security_group.bastion` | SSH from `admin_cidr`, HTTP 80 from the internet, NAT traffic from the private subnet |
| **Security group** app | `aws_security_group.app` | SSH and the API port **from the bastion's security group only** |
| **Security group** database | `aws_security_group.database` | 5432 **from the app's security group only**; no egress |
| Default security group | `aws_default_security_group.default` | Emptied, so nothing can use it by accident |
| **Bastion EC2** (t3.micro) + Elastic IP | `aws_instance.bastion`, `aws_eip.bastion` | Jump host for SSH and Ansible, nginx reverse proxy, NAT for the private subnet |
| **App EC2** (t3.micro), fixed private IP `10.20.2.10` | `aws_instance.app` | Runs the Docker container |
| SSH key pair | `aws_key_pair.admin` | Your public key, installed for the `ubuntu` user |
| **Amazon RDS for PostgreSQL** 16 (db.t4g.micro) | `aws_db_instance.main` | Managed DB: not public, encrypted, TLS enforced, automated backups, connection logging |
| DB subnet group + parameter group | `aws_db_subnet_group.main`, `aws_db_parameter_group.main` | Placement; `rds.force_ssl`, `log_connections`, `log_disconnections` |
| **Amazon ECR** repository | `aws_ecr_repository.app` | Private image registry; scan on push; keeps the 10 newest images |
| **GitHub OIDC provider + deploy role** | `aws_iam_openid_connect_provider.github`, `aws_iam_role.github_deploy` | Lets only this repo's `production` environment deploy, with no stored AWS keys |
| DB password | `random_password.postgres` | A generated 32-character password |

Both VMs: Ubuntu 24.04, SSH key login only (passwords disabled), IMDSv2 only,
encrypted gp3 disks, and **no IAM role** (they never hold AWS credentials).

### Why the bastion is also a NAT
The app VM has no public IP but still needs outbound internet for apt, Docker
and ECR pulls. A managed NAT gateway costs about US$32 a month, more than the
rest of the environment. Instead, the bastion forwards and masquerades the
private subnet's traffic: `source_dest_check = false`, a boot script in
`templates/bastion-nat.sh.tftpl` (IP forwarding + iptables `MASQUERADE`), and
a UFW route rule that Ansible adds. See [../SECURITY.md](../SECURITY.md).

## Variables

Required: `region`, `admin_cidr` (your IP as `/32`, and `0.0.0.0/0` is
rejected) and `ssh_public_key`. Everything else has a default; see
`variables.tf`: `prefix`, the CIDRs, `app_private_ip`, `app_port`, the
instance types, `postgres_version`, `db_instance_class`,
`db_backup_retention_days`, `image_repository`, `github_repository`,
`create_github_oidc_provider`, `tags`.

No secrets are passed in. The database password is generated by Terraform, and
AWS authentication uses your AWS CLI credentials.

| Output | Used for |
|--------|----------|
| `app_url` | The live app (`http://<bastion-ip>`) |
| `bastion_public_ip`, `app_private_ip`, `admin_username` | Ansible inventory, CD variables |

## How to use it

```bash
# 1. Sign in (use an IAM user or IAM Identity Center, not the root account)
aws configure                      # or: aws configure sso && aws sso login
aws sts get-caller-identity        # check which account you're in

# 2. Your values
cp terraform/terraform.tfvars.example terraform/terraform.tfvars
#    region: e.g. eu-west-1
#    admin_cidr: "$(curl -s ifconfig.me)/32"
#    ssh_public_key: contents of ~/.ssh/id_ed25519.pub

# 3. Initialise, check, plan, apply
cd terraform
terraform init
terraform fmt -check && terraform validate
terraform plan -out=tfplan        # review: about 35 resources to add
terraform apply tfplan            # about 10 minutes; RDS is the slowest part
terraform output

# 4. Tear down when finished (stops all charges)
terraform destroy
```

Next: `bash scripts/setup-github-deploy.sh` from the repo root (connects the CD
pipeline), then the first deploy. See the [main README](../README.md#5-deploy-to-aws-first-time).

### Tips
- **`EntityAlreadyExists` for the OIDC provider:** your account already has the
  GitHub provider. Set `create_github_oidc_provider = false` and apply again.
- **RDS says the backup retention exceeds the free tier maximum:** keep
  `db_backup_retention_days = 1` (the default). Paid accounts can use 7.
- **An instance type isn't available in the region:** change
  `bastion_instance_type` / `app_instance_type` (e.g. `t2.micro`) or
  `db_instance_class` (e.g. `db.t3.micro`).
- **af-south-1 (Cape Town)** is the closest region to Rwanda, but it is opt-in:
  enable it under Account → AWS Regions first.

## State

State is local (`terraform/terraform.tfstate`, ignored by Git) and **contains
the generated DB password**. Keep it private and don't delete it while the
environment exists. For a team you would move it to an S3 backend with
locking.
